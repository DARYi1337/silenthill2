# ARCHITECTURE — Fogbound
Версия: 0.2 · Одна сцена, модульная монолитная игра без избыточных абстракций.

## 1. Слои
1. **Платформа:** Windows, Python, Panda3D и Ursina.
2. **Core:** запуск, жизненный цикл, состояния игры, соединение подсистем.
3. **Системы:** игрок, камера, мир, взаимодействия, сценарий, аудио, освещение/туман, UI.
4. **Контент:** геометрия, зоны, интерактивные предметы, звуки, сценарные условия.

Это логические слои, а не обязательная иерархия наследования. Ursina управляет основным игровым циклом; свой движок и ECS не создаём.

## 2. Основные компоненты
- `Game`: создаёт сцену и подсистемы, управляет `PLAYING`, `PAUSED`, `ENDING` (меню опционально).
- `PlayerController`: ввод движения, физика/коллизии, положение персонажа.
- `CameraController`: вращение мышью, плавное следование, ограничения угла, при необходимости защита от прохождения через стены.
- `Level`: единая сцена и расстановка объектов; `Zone` — логическая область с триггером.
- `InteractionSystem`: находит доступный объект в радиусе/направлении взгляда, вызывает его `interact()` и обновляет подсказку.
- `GameState`: минимальные флаги прогресса (`has_key`, `read_note`, `final_unlocked`).
- `ScenarioController`: проверяет условия одноразовых событий и запускает действия.
- `EventBus`: необязательный простой механизм событий, вводить лишь при реальной необходимости развязать модули.
- `AudioManager`: эмбиент, позиционные эффекты, регулировка громкости.
- `Lighting` / `Fog`: визуальные настройки, независимые от правил прогресса.
- `HUD`: контекстная подсказка, записка, финальный экран.

## 3. Потоки взаимодействия
**Дверь:** клавиша E → InteractionSystem → проверка дистанции и условий → `Door.interact()` → обновление GameState при необходимости → ScenarioController запускает связанные звук/свет.

**Атмосферное событие:** вход в Zone → ScenarioController проверяет `triggered` и прогресс → AudioManager воспроизводит шаги → Lighting изменяет фонарь → событие помечается завершённым.

**Обновление кадра:** Ursina вызывает update → ввод/движение → камера → проверка взаимодействий/триггеров → сценарные события → визуальное обновление. Не создавать отдельный бесконечный игровой цикл.

## 5. Принципы зависимостей
- Core знает о системах, системы не импортируют `main.py`.
- Игрок не зависит от конкретной модели; камера не управляет прогрессом.
- UI читает состояние и отображает его, а не принимает сценарные решения.
- Контент не должен содержать низкоуровневый код рендеринга.
- Простая прямая функция предпочтительнее EventBus, если связей мало.
- Туман сначала штатный, без обязательной постобработки.

## 6. Производительность
Целевая платформа — Windows, 16 ГБ RAM, интегрированная графика. Начать с примитивов, небольших текстур, простого освещения и ограниченной дальности видимости. Проверять FPS на реальном ПК; целевой ориентир 30+ FPS, не гарантия.

## 7. Проверка изменений
Каждая задача должна оставлять запускаемый проект. Тестировать старт, управление, отсутствие ошибок в консоли, взаимодействие и прохождение до финала. При изменении контрактов между системами обновлять документ.
